# Craft UI 设计完善方案：借鉴 HeroUI，演进现有组件

实施记录与验收限制见 [实施报告](ui-design-system-refinement-implementation-2026-09-09.md)。

- 日期：2026-09-09
- 状态：设计与实施规划；产品代码尚未实施
- 已确认方向：借鉴 HeroUI 的设计方法，完善现有组件
- 目标：提升整体质感、交互完整性与跨页面一致性，同时控制渲染成本
- 实施方式：默认单任务顺序推进；下文阶段表示依赖和验收边界，不代表开启并行任务

## 1. 设计决策

保留 Craft 的 React、Tailwind、Radix、现有组件封装及主题引擎。将 HeroUI 的语义层级、控件状态和组合式表单方法转化为 Craft 自己的规范。

这轮的产品视觉方向是：**中性工作台、清晰表面、精确控件、稳定反馈。**

| 设计决定 | 具体约束 |
| --- | --- |
| 中性主操作 | 沿用 foreground/background 的主按钮，不把全产品主操作改为紫色 |
| 强调色有固定职责 | accent 用于当前选择、焦点及已有业务强调；状态色继续表达状态 |
| 通过关系建立层次 | 优先调整文字、间距、边界和表面；默认主题只保留必要的轻阴影 |
| 保留工作台密度 | 工具栏、列表、表单、阅读区各有适合的密度，不能统一放大成展示型网站 |
| 状态完整 | 默认、悬停、按下、键盘焦点、选中、禁用、加载、错误均有明确表达 |
| 自定义主题继续有效 | 保留用户主题文件、语义含义和深度能力；默认主题审美不限制用户主题风格 |
| 性能有实测依据 | 本轮先保证无明确回退；算法和加载优化仅在测量确认后进入独立任务 |

本轮不引入 HeroUI/React Aria 运行时、HeroUI 全局 CSS、新主题编辑器、新图标库或新的设计平台。页面导航、会话数据流、编辑器、表格引擎和原生窗口行为不因视觉完善而重写。

### 从 HeroUI 吸收什么

吸收操作主次、组合式控件、统一状态与样式/逻辑分离的方法；其具体颜色、尺寸和 API 不作为 Craft 的标准。[HeroUI 设计原则](https://heroui.com/en/docs/react/getting-started/design-principles)

字段采用标签、输入、说明、校验消息的稳定结构；选择器补齐分组、空结果、加载等实际需要的状态。[TextField](https://heroui.com/en/docs/react/components/text-field)、[Select](https://heroui.com/en/docs/react/components/select)

## 3. 全局视觉规范

以下数值是设计起点，不是性能测量或已经验收的最终结果。尺寸以默认字体和默认缩放为参照；实现优先用相对单位，并验证用户字体设置。

### 3.1 色彩、表面与材质

| 角色 | 现有变量/能力 | 设计规则 |
| --- | --- | --- |
| 应用底面 | background | 安静、连续；不为每个区域增加独立底板 |
| 导航表面 | navigator | 继续遵循显式配置才覆盖原生透明侧栏的规则 |
| 内容表面 | paper / card / background-elevated | 独立对象可有轻抬升，普通分组优先用留白和分隔线 |
| 字段表面 | input | 形成可编辑区域；同组字段底色、边界和高度一致 |
| 浮层表面 | popover / popover-solid | 文字可读优先，scenic 下仍保证要求不透明的浮层不透明 |
| 正文与辅助文字 | foreground / muted-foreground | 通过语义选择，不在弱化文字上继续层层叠透明度 |
| 弱背景 | muted / secondary | 保留现有背景语义，不映射成 HeroUI 的弱文字色 |
| 交互边界 | border / ring | 普通分隔、可操作边界、键盘焦点分开表达 |
| 业务状态 | success / info / destructive | 颜色搭配文字或图标，不能只靠颜色识别结果 |

默认主题的卡片采用轻边界，阴影只服务于层级。弹层和拖拽可以更强；嵌套分组不连续叠加外框、底色和阴影。深色主题主要依靠表面明度、边界和文字建立层次，不机械复制浅色投影。

默认交付继续保留 flat/elevated/neon/glass/raised 的主题能力；组件通过深度语义取值，不写死只能用于默认主题的阴影。玻璃模糊继续局限在需要的表面，不为每个列表项或输入框新增模糊层。

### 3.2 排版

| 信息角色 | 默认设计起点 | 应用方式 |
| --- | --- | --- |
| 页面标题 | 18–20px，medium/semibold | 设置等独立页面；不放大已有紧凑面板标题 |
| 面板标题、主要控件 | 13–14px，medium | 顶栏、导航、按钮，沿用场景原有结构 |
| 表单标签、列表主标题 | 13–14px | 保证中文、英文和混合名称都清楚 |
| 说明、次行、普通元信息 | 12–13px | 长说明允许换行，不通过极淡颜色压低权重 |
| 紧凑工具/数据区域 | 11–12px | 延续已修复的 Run 等场景；只用于适合紧凑排版的信息 |
| 聊天正文、文档阅读 | 保留当前阅读字号与用户偏好 | 不随工具栏密度一起缩小 |
| 代码、路径、数值 | 现有 mono 与数字样式 | 标识符可以等宽，普通说明继续使用正文字体 |

统一的是角色，不是把所有 `text-xs/text-sm` 替换成同一个数字。时间、数量等稳定元信息可用 tabular numbers；长文本通过换行、截断和详情入口处理。必须显示的错误、警告和操作说明不能只有被截断的单行版本。

### 3.3 尺寸、间距与密度

| 类型 | 默认起点 | 约束 |
| --- | --- | --- |
| 主框架图标按钮 | 28 × 28px | 保留既有标题栏几何尺寸和 no-drag 区域 |
| 小按钮/紧凑单行字段 | 32px 高 | 列表工具、次级动作 |
| 标准按钮/单行字段 | 36px 高 | 设置页和普通弹窗 |
| 大按钮 | 40px 高 | 少量独立流程，避免扩散到工具栏 |
| 触摸主要控件 | 目标命中区域至少 44 × 44 CSS px | 本项目设计目标；不通过重叠的隐形区域抢占相邻控件 |
| 图标 | 通常 14–16px | 继续使用现有图标族与主题描边设置 |
| 标签→说明 | 4px 起点 | 有说明时建立阅读间隔；无说明不预留空行 |
| 字段标签区→控件 | 8px 起点 | 同组一致 |
| 动作组间距 | 8px 起点 | 取消/保存、相邻工具动作 |
| 组内水平 padding | 12–16px 起点 | 依据已有卡片和面板边界统一 |
| 区块间距 | 20–24px 起点 | 表单区块；不是聊天轮次的通用间距 |

密度只作用于相应内容的 padding、gap 和允许变化的最小高度。标题栏、安全区、拖拽命中区、图标尺寸和面板最小宽度继续独立。沿用现有 compact/comfortable/cozy 枚举与倍率，不增加新的全局缩放设置。

圆角从主题 radius 派生为控件、卡片、浮层三个角色。先对照现有 `--radius-*` 映射取值，避免新增另一套大小刻度。桌面 28px 图标按钮通过共享角色样式统一圆角，不在每个包装组件各自写像素值。

### 3.4 状态视觉矩阵

| 状态 | 视觉 | 行为 |
| --- | --- | --- |
| 默认 | 角色决定背景和边界 | 操作名称明确 |
| Hover | 轻背景或边界变化 | 列表和文字不缩放、不位移 |
| Pressed | 按钮沿用轻按压；列表只改变表面 | 命中区域和布局稳定 |
| Focus-visible | 清晰独立的焦点轮廓 | 不把鼠标悬停等同于键盘焦点 |
| Selected / Open | 稳定的底色、标记或指示器 | hover 不抹去选中；焦点仍可单独辨认 |
| Disabled | 降低强调并阻止操作 | 必要原因在可访问的相邻说明中，不仅依赖禁用元素 Tooltip |
| Loading / Pending | 固定槽位 spinner、状态文案或静态进度 | 不抖宽，不重复提交；长任务保留取消动作 |
| Invalid / Error | 字段边界与具体错误文本 | 焦点仍可见，读屏关联错误；纠正方式明确 |
| Read-only | 保留可读性与必要选择/复制 | 不按 disabled 全面淡化 |
| Success | 明确完成结果，随后稳定 | 不对每次自动保存弹 Toast |

组合优先级：disabled 阻止交互；invalid 保留错误语义；focus-visible 叠加而非覆盖错误；selected 保留选择标记；hover/pressed 只改变相应表面。Loading 是否禁用、是否继续可聚焦按操作定义，不能用统一 CSS 推断。

焦点初始方案为清楚的轮廓及必要间隙，评审时从 2px 轮廓起步；复合字段在整个输入表面显示焦点，内部眼睛/清除按钮还需要独立可见的焦点。统一实现 focus 样式，避免全局 `outline:none` 后无替代。

### 3.5 动效

| 场景 | 规则 |
| --- | --- |
| 控件颜色与按压 | 沿用 fast 100ms，按压缩放沿用现有 0.98；不扩散至整行列表 |
| 同级内容切换 | 沿用 standard 160ms 短淡入，保持位置与已加载状态 |
| Dialog / 普通 Popover | 保持已交付的 160ms 入场、100ms 退场淡入淡出 |
| 高频菜单 | 保持即时响应，不恢复历史缩放和滑入 |
| 布局展开 | 必要时沿用 160–220ms；不对流式内容持续执行布局动画 |
| 拖拽/调整宽度/地图滚轮 | 直接跟随用户；保留已有独立的定位动画行为 |
| 持续运行反馈 | 同一区域一个主要活动信号；不可见时没有新增持续循环工作 |
| Reduced motion | 保留静态状态，停位移和循环；同时覆盖 CSS 与 JS |

现有 `motion.css` 和 `lib/motion.ts` 为唯一规范来源，不另建 HeroUI 动效体系。新增样式显式列出 transition 属性；不为装饰引入常驻 `will-change`、高频滤镜或无限动画。

### 4.1 操作按钮的使用约定

继续使用 `variant=default/secondary/outline/ghost/link/destructive`，先统一使用语义，不为了命名类似 HeroUI 而重写调用点。

| 产品意图 | 使用方式 |
| --- | --- |
| 保存、确认等当前主要动作 | default，中性实底；一个操作组通常只突出一个主要动作 |
| 替代动作、次要独立动作 | secondary 或 outline，取决于是否需要独立边界 |
| 取消、关闭、工具栏动作 | ghost；文字链接仅用于适合链接表达的行为 |
| 删除、撤销授权等危险动作 | destructive；是否需要确认继承业务规则，不一律新增弹窗 |
| 独立图标动作 | 共享图标按钮样式、名称和焦点，Tooltip 是补充 |

loading 为可选增量能力。普通 button 保留原生事件；`asChild` 继续只接收单个合法子元素，不为 spinner 注入破坏 Slot 结构的兄弟节点。若该组合无法安全支持 loading，类型或开发检查应明确限制，调用方自行组合加载内容。

### 4.2 字段设计

推荐结构：标签 → 必要说明 → 输入表面（前缀/控件/尾部动作）→ 辅助或错误消息。

- Field 层负责 `id`、标签关联、说明/错误 ID 和布局；Input 保留原生输入能力。
- 外部 `id`、ref、事件、`aria-describedby` 必须保留；新增 ID 合并不能覆盖调用方的描述。
- 错误同时关联 `aria-invalid` 和描述文本，文字说明具体修正方式；不逐字输入就反复播报。
- 密码显隐、清空、复制等动作具有可访问名称、正常键盘路径；不得创建嵌套 button。
- 长说明在窄面板换行；必要信息不使用 truncate；字段 value 和 placeholder 职责分开。
- 单行输入支持常规、错误、禁用、只读、密码、前后缀、保存中；多行输入额外验证高度和滚动。
- SettingsRow 整行可点击时不再同时包裹交互子控件；复合操作改用普通容器和独立动作。
- 默认保持已有校验时机、保存方式及回调，改变交互业务规则须有独立理由。

### 4.3 列表和表格设计

会话列表统一“图标—标题—必要次行—尾部信息”结构。Hover 和 focus-within 都能发现尾部操作；触摸端使用现有菜单/长按路径。选中项即使未悬停也可识别，搜索匹配、多选、当前焦点与运行状态各有独立标记。

任务表格宽屏保留列对齐和数值可扫描性；窄面板沿用已实现的次行布局。实际二维数据、代码 diff 等允许横向滚动，不把全部专业表格强制变成卡片。

本轮不统一替换列表引擎。EntityList 当前遍历条目，后续若测到大列表成本，单独决定窗口化；视觉调整不增加每行测量、订阅和动画控制器。

### 4.4 浮层设计

沿用 Radix 的键盘和焦点行为，统一外观与封装接口。确认框以标题、说明、动作组三层构成；长内容只在明确区域内滚动，关闭与提交入口保持可达。

重点验证 Dialog 内 Select/Popover、右键菜单、Tooltip 与滚动容器的叠加；关闭内层不能误关外层，Escape 后回到合理触发点。浮层采用现有 z-index 语义，不新增任意层级常数。移动端沿用已存在的 Drawer/compact 分支。

## 5. 页面级应用方案

| 场景 | 期望观感与布局 | 必须保留的行为 | 验收样本 |
| --- | --- | --- | --- |
| 主框架/侧栏 | 标题和图标对齐，活动区域清楚，分隔轻 | 原生拖拽区、缩放、折叠、导航快捷键 | 三栏、窄导航、失焦窗口 |
| 会话列表 | 标题优先，运行/未读标记明确，尾部动作稳定 | 搜索、多选、右键、长按、分组 | 长标题、无结果、运行中 |
| 聊天 | 正文和工具执行层级清楚，引用/附件一致 | 流式、复制、搜索定位、历史加载 | 长文本、代码块、错误与恢复 |
| Composer | 编辑表面聚焦，附件/模型/发送按钮各有明确角色 | IME、粘贴、附件、斜杠/提及、取消运行 | 中文输入、长提示、多个附件 |
| Run / Trajectory / Map | 沿用修复后的轻层次，统一工具栏和状态 | 视口、筛选、Tab 状态保留、详情焦点 | 默认/深色、窄 Inspector |
| 项目/看板/日历 | 公共控件统一，业务色有稳定解释 | 自定义列色、拖拽、日期和视图状态 | 拖拽、长任务名、窄面板 |
| 设置 | 标签/说明层次明确，字段成组，对齐稳定 | 既有自动保存/显式保存逻辑 | 常规、校验失败、连接验证中 |
| 模型/平台连接 | 输入和连接状态分离，恢复动作就近 | 授权流程、密钥显隐、重试 | 成功、失效、离线、长模型名 |
| Files / Artifacts / Browser | 统一外壳、空态、工具栏和操作组 | 文件预览、编辑、接受/审阅、浏览器行为 | 空内容、加载失败、长路径 |
| Automations | 折叠卡简洁，展开表单遵循 Field 规范 | 调度、编辑、启停语义 | 无记录、运行中、表单错误 |
| Onboarding / 登录 | 保留独立流程的留白与品牌比例 | 连接和首轮配置 | 键盘、窄屏、错误恢复 |
| WebUI / Viewer | 同一控件规则，尊重网页/只读场景 | 安全区、移动缩放、分享阅读 | 触摸、浅深色、长会话阅读 |

设置页作为首个完整样板：包含文本输入、密码、选择器、开关、状态、保存动作和错误反馈。第二个样板为会话列表加 Composer，验证高密度工作台能否成立。样板使用真实组件与合成数据，不以独立 HTML 仿制品代替生产组件验收。

## 6. 实现架构与文件归属

```text
主题文件 / DEFAULT_THEME_FILE
            ↓ 现有 themeToCSS
现有语义变量：颜色、表面、形状、字体、密度、深度
            ↓ 可复用的控件角色样式与少量派生变量
原生 / Radix 基础组件
            ↓ Field、Settings、EntityRow、PanelHeader 等组合
页面与业务内容

独立的 motion.css / motion.ts 贯穿组件，不进入主题文件协议
```

### 6.1 Token 策略

1. 先列出现有变量及消费者，再新增。`--muted`、`--primary`、`--input` 等已有含义不变。
2. 允许新增内部控件变量，例如字段背景/边界/焦点、图标按钮半径、控件高度；仅在有多个消费者且现有变量不足时加入。
3. 颜色类新增值由现有语义变量派生，避免重新写默认紫色、灰阶和警告色。
4. 首轮不扩展用户 JSON schema。用户已有语义覆盖仍可传导到新控件样式；只有实证出现无法表达的需求才单独扩展。
5. 不把所有 CSS 变量都声明为 `@property`，也不依赖新的全局 Provider 或每控件主题 hook。
6. 组件库默认样式属于公共层，页面只决定布局和业务语义；个别特例留下理由，避免无法解释的长期覆盖。

### 6.2 样式与组件落点

| 落点 | 职责/改造范围 |
| --- | --- |
| `packages/ui/src/styles/` | 拟新增 `controls.css` 存放共享控件角色样式与必要派生变量；不重复定义主题根颜色 |
| `packages/ui/src/styles/index.css` | 引入公共控件样式，保留共享主题基线 |
| `apps/electron/src/renderer/index.css` | 引入同一公共样式，整理本轮触及的冲突规则；保留桌面特有行为 |
| `apps/webui/src/index.css` | 通过现有 Electron CSS 复用，避免第二次引入和新增重复 reset |
| `apps/viewer/src/index.css` | 通过共享 UI 引入，保留 viewer 的背景等有意差异 |
| `apps/electron/src/renderer/components/ui/` | 完善已有封装；拟新增轻量 `field.tsx`，具体结构在首个样板中验证 |
| `apps/electron/src/renderer/components/settings/` | 使用 Field/控件角色规范，统一关联、密度与状态 |
| `packages/ui/src/components/` | 共享聊天、浮层和工具 UI 使用公共样式，不反向依赖 Electron |
| `apps/electron/src/renderer/playground/registry/` | 拟新增控件规范样例，复用现有注册与 Provider 机制 |

新样式以 `craft-` 前缀并明确 CSS layer，不复制 HeroUI 的 `.button/.input` 等全局类。现有 `data-slot`、Radix 的 `data-state`、ARIA 属性继续使用；仅缺少状态时增加必要属性，不建立平行状态系统。

跨端共用的轻量样式可以先集中；React 组件只有出现真实跨端消费者时才向共享包移动。本轮不把全部 Electron UI 迁到 `packages/ui`。不建立第二个组件入口目录，也不引入一次性的兼容框架。

需要构建验证 CSS import 顺序、layer 优先级、Tailwind source 范围及实际产物，避免“源码有类名、产物没有样式”。任意颜色字符串继续按完整 CSS 色处理，不能重新引入 `hsl(var(--background))` 一类分量假设。

## 8. 验收与性能约束

### 8.1 视觉和交互覆盖

采用“组件状态 × 代表场景”的最小有效组合，不对所有页面、所有主题做无意义的全排列。

| 维度 | 必须覆盖的代表情况 |
| --- | --- |
| 主题 | 默认浅色/深色；测试夹具验证小/大圆角、compact/cozy、flat/glass/raised；neon 验证状态可辨性；不写入用户主题目录 |
| 内容 | 中英文、长标签、长路径、空值、错误、多行说明；现有其他语言做改动字符串完整性检查 |
| 尺寸 | 宽工作台、420px 左右窄面板、390px 左右移动视口作为初始夹具；按实际布局断点补测 |
| 缩放 | 默认与较大文本/系统缩放；桌面窗口缩放及 WebUI 现有移动 zoom 组合 |
| 输入 | 鼠标、键盘、触摸代表流程、中文 IME |
| 焦点 | Tab/Shift+Tab、控件类型对应方向键、Enter/Space、Escape、嵌套浮层关闭恢复 |
| 生命周期 | 打开/关闭、loading→成功/失败、disabled、选中且聚焦、错误且聚焦 |
| 动效 | 默认和 reduced motion；运行时切换设置后反馈仍正确 |

默认主题的普通文字对比度目标至少 4.5:1，大文字至少 3:1；placeholder 也作为需检查的文字。使用实际合成后的前景/背景计算，不用截图抗锯齿像素代替颜色值。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

桌面目标尺寸参考 WCAG 2.2 的 24 × 24 CSS px 最小目标要求及其例外；44px 是本方案对主要触摸操作的更高设计目标，不是将所有控件强制放大的通用标准。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

键盘焦点不能被作者创建的内容完全遮挡；本项目同时检查浮层、固定工具栏和内部滚动对可见焦点的影响。[W3C 焦点不被遮挡说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)

上述是本轮局部验收目标，不等同于宣称整个产品通过 WCAG 认证。用户任意自定义颜色无法预先保证对比度，不在运行时悄悄改写用户配色。

### 8.2 性能测量

| 项目 | 方法 | 决策规则 |
| --- | --- | --- |
| 生产首屏 JS / CSS | 同一构建配置记录初始实际加载资源，区分原始/压缩体积；包括动态加载的公共 CSS | 出现不明增长，先解释依赖与样式来源，不以 tree-shaking 宣传代替结果 |
| 菜单/弹窗/设置打开 | 同一场景预热后重复操作，记录输入到可见反馈及主线程工作 | 只有可复现且超出运行波动的回退才判失败并定位 |
| 列表滚动 | 合成数据初始采用 100 / 1000 项，明确为测试规模；沿用当前列表实现 | 不增加每行测量、常驻动画或额外订阅；卡顿需 trace 定位 |
| 聊天流式 | 同一份脱敏或合成事件回放、同一输出速率、同样历史长度 | 比较 commit/主线程/滚动稳定性，不受模型网络输出速度干扰 |
| 空闲与隐藏视图 | 检查状态动画、定时器、观察器和残留挂载 | 不因装饰增加持续 JS 循环或资源泄漏 |
| 真正感知的稳定性 | 加载按钮宽度、错误消息插入、Tab 切换和列表尾部动作 | 无无故跳动、焦点丢失和滚动位置重置 |

M0 记录系统、应用/浏览器版本、构建类型、缩放、主题、样本和代码版本。普通交互预热后可先重复 5 次，比较中位数和范围；出现边缘差异才增加采样，不用小样本报告精确 p95。桌面/网页分别对比，不混用开发热更新和生产数据。

本轮不预设“快 20%”等收益，也不新增统一性能平台。若首次检查发现明显瓶颈，先判断是否由本轮变更造成；既有算法/首屏加载问题交由历史性能专项重新核验后处理。

### 8.3 最小必要检查

- 纯样式：真实浏览器视觉检查与计算样式为主，不编写验证类名字符串的测试。
- 行为变化：对 Field 关联、loading 重复提交、密码显隐键盘、嵌套浮层焦点等写聚焦测试。
- 修改共享 UI：运行其类型检查，并检查 Electron/WebUI/viewer 中受影响的消费者。
- 文案变化：补全对应 i18n 键与必要的 parity/排序检查。
- 完成一组代表性浏览器交互后，仅因新变更、失败或未消除的疑点追加测试；默认不跑全套。
- 实际 Electron 需要复验原生标题栏和窗口行为；浏览器截图不能替代这一步。无法完成的平台单列为未验证。

## 9. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 把“高级感”做成更多卡片和动效 | 按第 3 节评审表面职责；信息层级能用文字/留白解决时优先使用 |
| 覆盖 9 月 6 日已接受的结果 | 用修复后截图和行为作为基线；看板色彩、Map 视口、浮层即时菜单纳入回归 |
| CSS 优先级吞掉组件规范 | 在样板中检查计算样式与产物；只整理本轮相关冲突，避免全局 reset 重写 |
| 主题变量意义变化 | 不改变 muted 等语义；新增内部变量只做派生，不引入第二套主题真值 |
| 包装组件越来越重 | 优先共享 CSS，Field 保持轻量；不为每个基础控件新增 Context、Observer 或复杂运行时 |
| 视觉统一破坏桌面快捷交互 | 保留事件签名、asChild、no-drag、菜单/长按及 IME；行为检查与视觉一起完成 |
| 多端产生重复样式/分叉 | 明确唯一公共样式文件和现有导入链；viewer 的有意差异单独保留 |
| 历史文档与当前源码不一致 | 实施前复核触及路径；旧数据和旧 bug 不直接当现状 |
| 范围膨胀 | 每个组件以明确问题、角色和消费者进入；不借此重构数据流、路由、编辑器或主题存储 |

## 10. 完成定义与本轮交付边界

后续实施完成时应同时满足：

1. 高频基础控件有统一的视觉和状态规范，设置样板与主工作台样板均成立。
2. 页面改造覆盖表有记录；未改动组件和有意保留的专业布局有明确理由。
3. 默认浅/深主题、代表性自定义主题与窄面板验证通过；用户主题协议不被破坏。
4. 受影响的键盘、鼠标、触摸、IME 与浮层流程无已知阻断。
5. 已测核心场景没有无法解释的明显性能回退；没有把未测平台/真实超大数据描述为已通过。
6. 产物包含真实组件截图、变更与验证摘要、必要的例外和后续事项。

本次交付止于设计与规划。待进入实施时，以 M0 和首个实施切片为起点；本方案不代表产品代码已升级，也不自动启动历史性能专项。
